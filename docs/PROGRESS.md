# JobFlow — фактический прогресс

Дата: 2026-11-15. Локальный MVP подготовки откликов включает публичный поиск, ручную проверку, Google OAuth и подтверждаемый обмен с Sheets. Реальная отправка отключена. Ограничения относительно расширенного ТЗ перечислены ниже.

## Реализовано

- Несколько профилей, подтверждённые факты и предпочтения; версии PDF, выбор основного резюме, привязка версии к отклику.
- Аккаунты площадок: профиль кандидата, площадка, браузерный профиль, внешний ID резюме. Внешний ID сохраняется вручную, его существование на площадке не проверяется.
- Один workflow хранит произвольный выбор добавленных площадок и проходит по всему выбору при ручном и плановом запуске. Ошибка одного источника фиксируется в истории после обработки остальных.
- Сохраняемый workflow: discovery → правила/назначенный AI-оценщик → письмо из фактов/назначенный AI-автор → ReadyForReview. Редактор письма и явное одобрение. До 10 откликов за запуск; следующие обрабатываются при следующем запуске.
- Поиск: test-form извлекает встроенную синтетическую вакансию через Playwright; search-only обрабатывает вакансии из ручного/CSV/Sheets импорта. HeadHunter и Greenhouse используют официальные API поиска. Одобренный отклик можно открыть на площадке по ссылке.
- Правила: исключённые работодатели, навыки, локация, формат, уровень, зарплата/валюта, свежесть. Неизвестные данные требуют проверки, валюты автоматически не конвертируются.
- Codex CLI, проверка JSON Schema, версии агентов, шаблоны оценки/письма, журнал запусков. Других AI-провайдеров нет.
- MCP Client SDK 2.4.0: stdio и HTTP, discovery, read-only allowlist, явные аргументы инструментов перед вызовом агента. Произвольные действия по решению модели не разрешены.
- Защищённое отдельное хранилище секретов. Windows Data Protection + DPAPI; на Unix ключи защищаются правами ОС. Секреты не возвращаются API.
- CSV/Google Sheets: сопоставление колонок, preview → confirm, keep-local/update-vacancies, учёт дубликатов, история импортированных откликов, запрет повторной заявки по истории.
- Google OAuth для Gmail и Sheets использует loopback callback, PKCE, одноразовое состояние, защищённые токены и автоматическое обновление access token.
- Sheets write-back экспортирует снимок локальных откликов в отдельную вкладку с предпросмотром, проверкой изменений и записью RAW. Импорт и экспорт используют отдельные вкладки.
- Gmail metadata/snippet и JSON feedback: чтение, дедупликация, отметка обработки, ручная связь с отправленным откликом. Связь переводит Submitted → EmployerResponded; автоматической отправки писем нет.
- Worker: HealthCheck, BrowserDryRun, Workflow, Integration; интервалы, ручной запуск, пауза, остановка, тайм-аут 5–900 секунд, 0–5 повторов с backoff, 20-минутная lease, восстановление прерванных задач.
- Тестовая отправка после одобрения: попытка и идемпотентный ключ сохраняются до адаптера. TestConfirmed требует квитанции. Потеря подтверждения → SubmissionUnknown без автоматического повтора. После аварии Pending можно явно отметить неизвестным.
- Адаптивный Angular UI, история оценок, workflow, задач, интеграций, попыток и взаимодействий.

## Проверки

- Backend: сборка без предупреждений и ошибок.
- Angular production build: успешно, около 353 КБ исходных файлов / 85 КБ transfer estimate.
- 38 тестов прошли (7 unit и 31 integration). Отдельно проверены выбор нескольких площадок, исключение невыбранных и продолжение работы при ошибке одного источника. Проверены HTTP-контракты обоих адаптеров, повтор OAuth callback, refresh и устаревший предпросмотр Sheets. Тесты включают SQLite migrations, ownership/concurrency, workflow recovery, MCP stdio/HTTP, CSV и Google/Gmail HTTP fixtures, дедупликацию, неизвестный результат отправки, backoff, timeout/cancellation.
- Chromium smoke: создание профиля, reload/back navigation, фильтрация профилей, независимый Worker; полный workflow, редактирование/одобрение письма, TestConfirmed. Изолированная БД, синтетические данные; ошибок JavaScript нет.
- Реальный Codex CLI был проверен синтетическим schema-constrained запросом на предыдущем этапе.
- Google аккаунты не подключались: Google API проверены контролируемыми HTTP-ответами, а не live авторизацией.
- Linux, PostgreSQL и восстановление резервной копии на другой машине пока не проверены.

## Осталось до полного объёма исходного ТЗ

1. Автозаполнение реальных форм, дополнительные площадки и подтверждение фактической отправки. Текущие адаптеры ищут вакансии и передают пользователю ссылку.
2. Построчное двустороннее слияние в одном диапазоне Sheets, автоматическое расписание экспорта и история конфликтов. Текущий экспорт заменяет снимок выделенной вкладки после подтверждения.
3. Сквозной OAuth и Sheets write-back на Google-аккаунте пользователя. Автоматические проверки используют контролируемые HTTP-ответы.
4. Автоматическая классификация приглашений/отказов и сверка с площадками; сейчас события связывает человек.
5. Проверка актуальности внешних резюме, извлечение текста PDF, дополнительные AI/browser providers и возможности/лимиты моделей. Стоимость Codex контролируется вне JobFlow.
6. Политики хранения/редактирования персональных данных, эксплуатационный аудит, backup/restore drill, Linux smoke и упаковка служб. Для удалённого доступа нужны аутентификация и TLS; текущий MVP рассчитан на localhost.

## Продолжение и запуск

Из D:/Projects/JobFlow:
```powershell
pwsh -File scripts/build.ps1
dotnet test
dotnet run --project tests/JobFlow.Smoke
dotnet run --no-build --no-launch-profile --project src/JobFlow.Api
# Во втором терминале:
dotnet run --no-build --no-launch-profile --project src/JobFlow.Worker
```

Адрес http://127.0.0.1:5271. Для API и Worker используйте одинаковый JOBFLOW_DATA_DIR.
Перед обновлением сохраните резервную копию всего каталога данных при остановленных процессах: SQLite migrations могут перестраивать таблицы вне одной транзакции.
