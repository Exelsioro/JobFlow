# Настройка workflow и интеграций

## Подготовка откликов

Создайте профиль, загрузите PDF и площадку. Для локальной проверки используйте test-form: URL не посещается, данные искусственные. Для своих вакансий используйте search-only и импорт.

Для HeadHunter выберите `headhunter` и введите поисковый запрос. За запуск читается до 50 вакансий из [HeadHunter API](https://api.hh.ru/openapi/redoc). Для Greenhouse выберите `greenhouse`, задайте имя работодателя как название площадки и введите токен доски из URL, например `mycompany` для `job-boards.greenhouse.io/mycompany`. Вакансии читаются из [Job Board API](https://docs.greenhouse.io/job-board.html). После одобрения письма ссылка «Открыть вакансию» ведёт к форме площадки для ручной работы.

Создайте workflow, выберите профиль, площадку и конкретную версию PDF. Без агентов используются правила и шаблон письма из фактов. Для AI создайте включённый Codex-провайдер и агенты с шаблонами Evaluation/CoverLetter, затем назначьте их workflow.

Пример правил:
```json
{"requiredSkills":["C#"],"locations":["Remote"],"workModes":["remote"],"minimumSalary":3000,"currency":"USD","maxAgeDays":30,"levels":["middle"]}
```
Пустые правила {} допустимы. Неизвестные параметры не доказывают соответствие.

Запустите Worker, нажмите «Запустить workflow». Проверьте историю и оценки, отредактируйте письмо и одобрите ReadyToSubmit. Только test-form имеет кнопку тестовой отправки. Для реальных вакансий работа заканчивается подготовкой; отправляйте вручную на площадке.

## MCP

Укажите доверенный исполняемый файл и JSON-массив аргументов для stdio либо HTTPS endpoint для HTTP (HTTP допустим только localhost). Включите соединение, сохраните секреты отдельно и выполните discovery.

Секреты stdio — JSON-объект переменных окружения. Для HTTP — заголовки, например {"Authorization":"Bearer YOUR_TOKEN"}. Значения заменяются целиком; не помещайте их в аргументы, URL или промпты.

permissionsJson содержит массив разрешённых имён, например ["lookup_jobs"]. Инструмент должен объявлять readOnlyHint=true. В агенте toolBindingsJson:
```json
[{"connectionId":"UUID","toolName":"lookup_jobs","arguments":{"query":"C#"}}]
```
Это явно заданные вызовы перед AI, а не автономный выбор инструментов моделью. Подключайте только доверенные MCP-серверы.

## CSV и Google Sheets

Создайте интеграцию с профилем и площадкой. mappingJson сопоставляет внутренние имена с заголовками:
```json
{"externalId":"Id","title":"Title","employer":"Employer","url":"Url","description":"Description","applicationState":"Status"}
```
Id должен быть стабильным ID вакансии на выбранной площадке. Непустой Status означает исторический отклик и блокирует повторную заявку. Не используйте эту колонку для статуса вакансии.

CSV: загрузите файл до 5 МБ/5000 строк, просмотрите строки в «Импорт журналов», подтвердите. Предпросмотр не создаёт вакансии. keep-local сохраняет локальные вакансии; update-vacancies обновляет импортируемые поля. История и отправки не перезаписываются.

Sheets endpoint: https://sheets.googleapis.com/v4/spreadsheets/SPREADSHEET_ID/values/ENCODED_RANGE
Первая строка диапазона — заголовки. Подключите Google, включите интеграцию, прочитайте источник и подтвердите импорт.

Для записи создайте отдельную пустую вкладку в той же таблице. Имя вкладки может содержать латинские буквы, цифры, пробелы, дефисы и подчёркивания. Нажмите «Экспорт в Sheets», введите имя и проверьте оба набора значений. При подтверждении обновится диапазон A1:F501. В него попадут до 500 локальных откликов выбранного профиля и площадки без тестовых записей. Старые строки экспорта очищаются, значения пишутся в режиме RAW. Заголовок связывает вкладку с конкретной интеграцией. Изменения между предпросмотром и повторным чтением останавливают запись. API Sheets не поддерживает условную запись диапазона, поэтому выделенную вкладку следует оставить под управлением JobFlow. Импорт и экспорт работают на отдельных вкладках; построчного объединения изменений нет.

## Google OAuth

В Google Cloud включите нужные API, настройте OAuth consent screen и создайте клиент типа Desktop app. Если приложение в режиме Testing, добавьте свой аккаунт в список тестовых пользователей. Установите `JOBFLOW_GOOGLE_CLIENT_ID` и `JOBFLOW_GOOGLE_CLIENT_SECRET` в окружении API и Worker. Перезапустите оба процесса и откройте JobFlow через http://127.0.0.1:5271. В интеграции нажмите «Подключить Google», затем подтвердите доступ в Google. Callback использует loopback и одноразовое состояние с PKCE. Токены хранятся в зашифрованном хранилище, просроченный access token обновляется при запуске интеграции. Для Gmail запрашивается gmail.readonly, для Sheets — spreadsheets. При отозванном доступе подключите Google снова.

Ручной заголовок Authorization по-прежнему доступен в «Секретах». Сохранение набора заголовков заменяет сохранённый OAuth grant. Документация: [Google OAuth для Desktop apps](https://developers.google.com/identity/protocols/oauth2/native-app), [Sheets values.update](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/update).

## Gmail и JSON feedback

Gmail endpoint: https://gmail.googleapis.com/gmail/v1/users/me/messages?q=YOUR_URL_ENCODED_QUERY
Задайте узкий запрос по переписке о работе; сохраняются тема и snippet, не вложения/полное письмо. Для запросов q используйте подходящий Gmail readonly scope (metadata scope не поддерживает q). Подключите Google или сохраните Authorization отдельно. До 10 страниц за проверку; превышение требует сузить запрос и не считается успешной проверкой.

JSON endpoint возвращает массив:
```json
[{"sourceEventId":"stable-id","subject":"Interview","body":"Message","receivedAt":"2026-11-15T12:00:00Z"}]
```
Требуется HTTPS; localhost HTTP разрешён для тестов. Повторные sourceEventId в одной интеграции пропускаются.

В «Обратной связи» прочитайте сообщение, при необходимости свяжите его с отправленным откликом того же профиля. Ответы и календарные события не отправляются.

## Расписание

Создайте Integration-задание для сетевого источника либо редактируйте автоматически созданное Workflow-задание. Сам workflow и источник должны быть включены. Интервалы считаются в UTC; timezone хранится для настройки, cron нет.
Пауза прекращает будущие запуски. Остановить также запрашивает отмену активной работы. Максимальный тайм-аут 900 секунд, lease 20 минут. Повторы 1/2/4/8/16 минут; истёкшие lease восстанавливаются после перезапуска Worker.
