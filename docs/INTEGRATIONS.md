# Настройка workflow и интеграций

## Подготовка откликов

Для исходного сценария «войти в площадки → агент ищет и отправляет → почта и учёт» используйте режим workflow `browser`, общий браузерный профиль и шаблон агента `BrowserAutomation`. Пошаговая настройка находится в [README](../README.md#браузерный-поиск-и-автоматические-отклики). Этот режим использует браузерные авторизации. Описанный ниже `prepare` использует API/импорт и ручное одобрение.

Создайте профиль, загрузите PDF и площадку. Для локальной проверки используйте test-form: URL не посещается, данные искусственные. Для своих вакансий используйте search-only и импорт.

Для HeadHunter выберите `headhunter` и введите поисковый запрос. За запуск читается до 50 вакансий из [HeadHunter API](https://api.hh.ru/openapi/redoc). Для Greenhouse выберите `greenhouse`, задайте имя работодателя как название площадки и введите токен доски из URL, например `mycompany` для `job-boards.greenhouse.io/mycompany`. Вакансии читаются из [Job Board API](https://docs.greenhouse.io/job-board.html). После одобрения письма ссылка «Открыть вакансию» ведёт к форме площадки для ручной работы.

Добавьте нужные источники в «Площадки». В настройках workflow выберите профиль, версию PDF и отметьте нужные площадки. Кнопка «Выбрать все площадки» отмечает весь текущий список. Новые площадки добавляются в сохранённый список при редактировании workflow. Один ручной или плановый запуск проходит по всем выбранным источникам. Для площадок без поискового адаптера выберите `search-only` и импортируйте вакансии вручную или через журнал. Без агентов используются правила и шаблон письма из фактов. Для AI создайте включённый Codex-провайдер и агенты с шаблонами Evaluation/CoverLetter, затем назначьте их workflow.

Пример правил:
```json
{"requiredSkills":["C#"],"locations":["Remote"],"workModes":["remote"],"minimumSalary":3000,"currency":"USD","maxAgeDays":30,"levels":["middle"]}
```
Пустые правила {} допустимы. Неизвестные параметры не доказывают соответствие.

Запустите Worker, нажмите «Запустить workflow». Проверьте историю и оценки, отредактируйте письмо и одобрите ReadyToSubmit. Только test-form имеет кнопку тестовой отправки. Для реальных вакансий можно заполнить черновик в браузере и отправить его вручную.

## Заполнение формы в браузере

Создайте браузерный профиль и привяжите его к кандидату и площадке в «Аккаунты площадок». Одобрите черновик и нажмите «Заполнить в браузере». В открывшемся окне войдите на сайт при необходимости и откройте форму отклика в той же вкладке. В JobFlow нажмите «Проверить открытую форму», проверьте адрес и поля и подтвердите заполнение.

JobFlow поддерживает обычные HTML-формы с распознаваемым полем письма или загрузки резюме. Заполняются распознанные пустые поля полного имени, email и письма. Вложения, вопросы без известного ответа и согласия проверяет пользователь. Формы во фреймах и нестандартные виджеты пока требуют ручной работы. JobFlow не нажимает кнопку отправки. После самостоятельной отправки можно зафиксировать её кнопкой «Отметить отправленным вручную».

## MCP

Укажите доверенный исполняемый файл и JSON-массив аргументов для stdio либо HTTPS endpoint для HTTP (HTTP допустим только localhost). Включите соединение, сохраните секреты отдельно и выполните discovery.

Секреты stdio — JSON-объект переменных окружения. Для HTTP — заголовки, например {"Authorization":"Bearer YOUR_TOKEN"}. Значения заменяются целиком; не помещайте их в аргументы, URL или промпты.

permissionsJson содержит массив разрешённых имён, например ["lookup_jobs"]. Инструмент должен объявлять readOnlyHint=true. В агенте toolBindingsJson:
```json
[{"connectionId":"UUID","toolName":"lookup_jobs","arguments":{"query":"C#"}}]
```
Это явно заданные вызовы перед AI, а не автономный выбор инструментов моделью. Подключайте только доверенные MCP-серверы.

## CSV и Google Sheets

Создайте интеграцию с профилем и площадкой. mappingJson сопоставляет внутренние имена с заголовками:
```json
{"externalId":"Id","title":"Title","employer":"Employer","url":"Url","description":"Description","applicationState":"Status"}
```
Id должен быть стабильным ID вакансии на выбранной площадке. Непустой Status означает исторический отклик и блокирует повторную заявку. Не используйте эту колонку для статуса вакансии.

CSV: загрузите файл до 5 МБ/5000 строк, просмотрите строки в «Импорт журналов», подтвердите. Предпросмотр не создаёт вакансии. keep-local сохраняет локальные вакансии; update-vacancies обновляет импортируемые поля. История и отправки не перезаписываются.

Sheets endpoint: https://sheets.googleapis.com/v4/spreadsheets/SPREADSHEET_ID/values/ENCODED_RANGE
Первая строка диапазона — заголовки. Подключите Google, включите интеграцию, прочитайте источник и подтвердите импорт.

Для записи создайте отдельную пустую вкладку в той же таблице. Имя вкладки может содержать латинские буквы, цифры, пробелы, дефисы и подчёркивания. Нажмите «Экспорт в Sheets», введите имя и проверьте оба набора значений. При подтверждении обновится диапазон A1:F501. В него попадут до 500 локальных откликов выбранного профиля и площадки без тестовых записей. Старые строки экспорта очищаются, значения пишутся в режиме RAW. Заголовок связывает вкладку с конкретной интеграцией. Изменения между предпросмотром и повторным чтением останавливают запись. API Sheets не поддерживает условную запись диапазона, поэтому выделенную вкладку следует оставить под управлением JobFlow. Импорт и экспорт работают на отдельных вкладках; построчного объединения изменений нет.

## Google OAuth

В Google Cloud включите нужные API, настройте OAuth consent screen и создайте клиент типа Desktop app. Если приложение в режиме Testing, добавьте свой аккаунт в список тестовых пользователей. Установите `JOBFLOW_GOOGLE_CLIENT_ID` и `JOBFLOW_GOOGLE_CLIENT_SECRET` в окружении API и Worker. Перезапустите оба процесса и откройте JobFlow. В интеграции нажмите «Подключить Google», затем подтвердите доступ в Google. Для Desktop OAuth один раз откройте http://127.0.0.1:5271/#integrations в обычном браузере на компьютере с JobFlow и нажмите «Подключить Google». При доступе по LAN интерфейс показывает эти инструкции: Google может отклонять автоматизированные браузеры, а loopback callback должен вернуться на компьютер с API. После подключения мониторинг работает независимо от браузера. Callback использует loopback и одноразовое состояние с PKCE. Токены хранятся в зашифрованном хранилище, просроченный access token обновляется при запуске интеграции. Для Gmail запрашивается gmail.readonly, для Sheets — spreadsheets. При отозванном доступе подключите Google снова.

Ручной заголовок Authorization по-прежнему доступен в «Секретах». Сохранение набора заголовков заменяет сохранённый OAuth grant. Документация: [Google OAuth для Desktop apps](https://developers.google.com/identity/protocols/oauth2/native-app), [Sheets values.update](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/update).

## Gmail и JSON feedback

Gmail endpoint: https://gmail.googleapis.com/gmail/v1/users/me/messages?q=YOUR_URL_ENCODED_QUERY
Задайте узкий запрос по переписке о работе; сохраняются тема и до 12 000 символов текста сообщения. Вложения не загружаются. Для запросов q используйте подходящий Gmail readonly scope (metadata scope не поддерживает q). Подключите Google или сохраните Authorization отдельно. До 10 страниц за проверку; превышение требует сузить запрос и не считается успешной проверкой.

JSON endpoint возвращает массив:
```json
[{"sourceEventId":"stable-id","subject":"Interview","body":"Message","receivedAt":"2026-11-15T12:00:00Z"}]
```
Требуется HTTPS; localhost HTTP разрешён для тестов. Повторные sourceEventId в одной интеграции пропускаются.

После фактической отправки на сайте нажмите «Отметить отправленным вручную» у одобренного отклика. Gmail распознаёт приглашения и отказы и связывает сообщение автоматически при единственном совпадении по ссылке на вакансию или маркеру [JobFlow:GUID] с отправленным откликом этого профиля. Неоднозначные сообщения остаются для ручной привязки. За запуск обрабатывается до 25 новых или ранее не разобранных сообщений. Для отдельной модели создайте агента по шаблону «Шаблон разбора почты», включите его и выберите в Gmail-интеграции. Модель получает тему и до 4000 символов текста. Без агента работают встроенные правила. Ответы и календарные события не отправляются.

## Статусы на площадках

Для HeadHunter создайте интеграцию hh-status для профиля и площадки с endpoint `https://api.hh.ru/negotiations`. Сохраните в секретах Authorization с OAuth-токеном соискателя и HH-User-Agent с именем приложения и контактным email. Список откликов соискателя читается через [официальный API HeadHunter](https://api.hh.ru/openapi/en/redoc).

Для других площадок настройте status-json только при наличии авторизованного источника. Он должен возвращать массив:
```json
[{"externalVacancyId":"123","status":"Invitation","observedAt":"2026-11-15T12:00:00Z"}]
```
Допустимые значения Pending, Viewed, Invitation, Rejection, Offer и Hired. Обновления сопоставляются по профилю, площадке и внешнему ID вакансии. Старое наблюдение не перезаписывает новое. Проверка выполняется по выбранным площадкам во время workflow или отдельно через расписание Integration. Публичная доска Greenhouse сама по себе не даёт статусы откликов.

## Расписание

Создайте Integration-задание для сетевого источника либо редактируйте автоматически созданное Workflow-задание. Сам workflow и источник должны быть включены. Интервалы считаются в UTC; timezone хранится для настройки, cron нет.
Пауза прекращает будущие запуски. Остановить также запрашивает отмену активной работы. Максимальный тайм-аут 900 секунд, lease 20 минут. Повторы 1/2/4/8/16 минут; истёкшие lease восстанавливаются после перезапуска Worker.
